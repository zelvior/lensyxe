## Global flags

Available on every command.

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--config <path>` | *(none)* | Path to an Lensyxe config file. When unset, `.lensyxe.yml` is discovered from the working directory, then from the parent directories. |
| `--help` | — | Command usage. |
| `--version` | — | Same output as `lensyxe version`. |

## Exit codes

| Code | Meaning | When |
| ---: | :--- | :--- |
| `0` | Success | The analysis completed and no configured threshold was breached. |
| `1` | Failure | Bad path, unreadable config that could not be recovered from, an analyzer crash, or a usage error. |
| `2` | Policy rejection | A threshold configured in `.lensyxe.yml` or via a `--fail-*` flag was breached. |

Exit code `2` is deliberately distinct from `1`. A pipeline can treat `1` as
"something broke" and `2` as "the gate rejected this code", which is the
difference between a bug report and a rejected pull request.

The report is printed and the snapshot is recorded **before** the gate is
evaluated, so a rejected run still leaves evidence of what it looked like.

## `lensyxe analyze`

Analyze a repository and report its Engineering Health Score.

```
lensyxe analyze [path]
```

`path` defaults to the working directory. The code, git, and dependency
analyzers run concurrently, so wall-clock time is bounded by the slowest
analyzer rather than by their sum.

### Output

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--format <fmt>` | `terminal` | `terminal`, `markdown`, or `json`. Markdown is written without ANSI escapes so it pastes cleanly into a pull request. |
| `--findings` | `false` | Include raw findings in markdown output. |
| `--monorepo` | `false` | Detect a workspace layout and score each package individually. Overrides `detect_workspace` from the config file for this run. |

### Recording

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--no-persist` | `false` | Do not write this snapshot to the history database. |
| `--no-gate` | `false` | Skip threshold checks for this run. |

### Overrides

These read the same settings as the config file and take precedence over it.

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--git-window <days>` | `90` | Days of git history to analyze. |
| `--hotspot-threshold <lines>` | `400` | Code lines at or above which a file becomes a hotspot **candidate**. |
| `--timeout <seconds>` | `60` | Overall scan timeout. `0` disables the deadline. |

### CI gates

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--fail-under-health <score>` | *(unset)* | Exit `2` when the health score is below this value, 0–100. |
| `--fail-on-critical-risk` | `false` | Exit `2` when any critical risk is detected. |
| `--fail-on-test-ratio-drop <pp>` | *(unset)* | Exit `2` when the test-to-code file ratio falls by more than this many percentage points. Requires `--baseline`; skipped without one. |
| `--fail-on-coverage-drop <pp>` | *(unset)* | **Rejected.** Lensyxe does not measure code coverage. Use `--fail-on-test-ratio-drop`. |
| `--workflow-fail-severity <sev>` | `none` | Also exit `2` when a `.github/workflows` finding reaches this severity or worse: `critical`, `high`, `medium`, `low`, `none`. |
| `--pr-comment <path>` | *(none)* | Write a pull-request comment body to this file. A `.json` suffix wraps the body with metadata. |
| `--baseline <path>` | *(none)* | Snapshot JSON to compare against. Without it no deltas are computed. |

### AI explanation

See [SCORING_SPEC.md](SCORING_SPEC.md#the-ai-explanation-layer) for the
guarantees this layer makes.

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--explain` | `false` | Append a natural-language summary. Requires a provider and key; with neither, a note is printed and the run is unaffected. |
| `--ai-provider <name>` | `$LENSYXE_AI_PROVIDER` | `openrouter`, `openai`, or `gemini`. |
| `--ai-model <id>` | `$LENSYXE_AI_MODEL`, then the provider default | Model identifier. |
| `--ai-key-env <name>` | `LENSYXE_AI_KEY` | Environment variable **name** holding the key. |
| `--ai-timeout <duration>` | `45s` | Timeout for the request. |

### Examples

```bash
# Human-readable report, recorded to history.
lensyxe analyze

# Machine-readable, not recorded. This is what a pipeline wants.
lensyxe analyze . --format json --no-persist

# Fail a pipeline below 70, with a comment posted by the caller.
lensyxe analyze . --fail-under-health 70 --pr-comment /tmp/comment.md

# Compare against a stored base revision and reject a test-ratio regression.
lensyxe analyze . --baseline base.json --fail-on-test-ratio-drop 2

# Monorepo breakdown.
lensyxe analyze . --monorepo --format markdown
```

## `lensyxe status`

Show where a repository stands right now.

```
lensyxe status [path] [flags]
```

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--format <fmt>` | `terminal` | `terminal`, `json`, or `markdown`. |
| `--no-persist` | `false` | Accepted for symmetry with `analyze`; status never records a run. |

This is the same analysis `lensyxe analyze` performs, rendered in a few lines:
the score, the three dimensions, a risk count, and which dimension is weakest.
It is not a cheaper measurement, only a shorter rendering, so the score here and
the score in `analyze` always agree.

`status` does **not** record a run to the history database. Checking whether you
are healthy should not itself become an entry in your health history.

## `lensyxe setup`

Propose a `.lensyxe.yml` derived from a measurement of the repository.

```
lensyxe setup [path] [flags]
```

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--write` | `false` | Write the proposal to `.lensyxe.yml`. |
| `--force` | `false` | Replace an existing `.lensyxe.yml`. The old file is overwritten, not merged. |

The documented configuration file is a template: it lists every key with its
default. A template cannot know that this repository has a Rust `target`
directory, that its history is one day deep, or how long its own scan takes.
`setup` runs the analysis and proposes values from what it just measured:

- **`ignore_dirs`** — the build directories that are actually present. `node_modules`
  appears in both the always-pruned list and the detected-toolchain list, so the
  result is deduplicated rather than emitted twice.
- **`git_window_days`** — scaled to the real age of the history. A ninety-day window on a
  repository a week old reports a bus factor of one and near-zero cadence
  because nobody has had time to do anything, and both are reported as findings.
- **`timeout_seconds`** — four times the measured scan time, rounded up, never below the 60s
  default. Omitted entirely when the scan duration is zero, because a timeout
  derived from no measurement is a number derived from nothing.
- **`detect_workspace`** — only when a workspace layout was actually found.

### What it will not do

**It does not propose `hotspot_threshold`.** That value changes the code health
score. A wizard that quietly moves your score is worse than one that leaves it
alone, so the command reports how many files exceed the current threshold and
lets you decide.

**It does not put the CI thresholds in the config file.** `min_health_score`,
`require_tests`, and `fail_on_drift` are not configuration keys — the real
gates are the `--fail-under-health`, `--fail-on-critical-risk`, and
`--fail-on-test-ratio-drop` flags on `analyze`. Writing them into a config file
would produce a file that looks authoritative and is silently ignored on every
line. They are printed as a command line instead, with the threshold placed
below the current score so it catches regressions rather than failing on the
next unrelated commit.

**It does not enable the explanation layer.** That needs a key you supply, it is
the only outbound request this tool can make, and no number it proposes depends
on it.

A section titled `NOT CHANGED, AND WHY` lists everything the command declined to
set, with the reason. A proposal that silently omits a key reads as an oversight
rather than as a decision.

### Safety

Nothing is written without `--write`. An existing `.lensyxe.yml` is never
replaced without `--force` as well, and it is overwritten rather than merged —
the generated keys are a proposal, not a patch to your file. Keys the proposal
does not mention keep their built-in defaults, so deleting a line reverts that
one setting.

Rendering is byte-identical across runs on an unchanged repository, so
re-running it does not produce a diff.

## Git-style aliases

Several commands answer to a second name, so the spellings you already have in
your fingers work here. Aliases are not separate commands: they share the
implementation, the flags, and the documented behaviour, and cannot drift apart.

| Command | Also accepts | Note |
| :--- | :--- | :--- |
| `lensyxe analyze` | `an` | |
| `lensyxe status` | `st` | |
| `lensyxe history` | `log`, `lg` | Reads recorded health history. It does not read commit messages. |
| `lensyxe compare` | `diff`, `df` | |
| `lensyxe watch` | `w` | |
| `lensyxe serve` | `ui` | |

These are a naming convenience, not a claim to be a version control system.
`status` reads health and `log` reads recorded health runs; neither can stage,
commit, or push anything.

## `lensyxe compare`

Compare two revisions of a repository.

```
lensyxe compare <rev-a> <rev-b> [flags]
```

Both arguments are resolved through `git archive`, so the working tree is
never modified and uncommitted work is not included.

**The composite score is not on the same scale as `lensyxe analyze`.** A `git
archive` export contains no `.git`, so Maintainability cannot be measured and its
weight is redistributed across the dimensions that could be. On this repository,
`compare` reports 65.0 for a commit that `analyze` scores 67.3. The *delta* is
unaffected, because both revisions are measured the same way; only the absolute
number is. Use `analyze` for an absolute score and `compare` for the movement
between two revisions.

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--format <fmt>` | `terminal` | `terminal`, `markdown`, or `json`. |
| `--compare-root <dir>` | *(working directory)* | Repository to compare within. |
| `--timeout <seconds>` | `120` | Per-revision timeout. |

```bash
lensyxe compare HEAD~10 HEAD
lensyxe compare v1.0.0 v1.1.0 --format json
```

## `lensyxe history`

Render the recorded health timeline.

```
lensyxe history [path]
```

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--limit <n>` | `10`, or `history_limit` from the config | Number of runs to display. |
| `--title <text>` | *(derived from the path)* | Override the timeline heading. |
| `--grid` | `false` | Draw vertical rules between axis labels. |

The timeline is a **step plot**. Each column is one discrete measurement;
interpolating between runs would imply intermediate states that were never
observed.

```bash
lensyxe history
lensyxe history . --limit 50 --grid
```

## `lensyxe watch`

Re-analyze on every change and stream the score movement.

```
lensyxe watch [path]
```

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--debounce <ms>` | `250` | Milliseconds to coalesce filesystem events. Editors write a file in several operations; without a debounce one save triggers a burst of redundant scans. |
| `--interval <seconds>` | `0` | Also re-analyze every N seconds even when nothing changed. `0` reacts to changes only. |
| `--ext <list>` | *(analyzer default)* | Comma-separated file extensions to watch, for example `go,ts`. |

Press `Ctrl+C` to stop.

```bash
lensyxe watch
lensyxe watch ./packages/api --ext go --debounce 100
```

## `lensyxe serve`

Serve the local dashboard and its JSON API from one process.

```
lensyxe serve [path]
```

The analysis runs once at startup, not per request, so opening the page
repeatedly does not re-scan the repository. Use the dashboard's Reload button
or restart the command to refresh.

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--port <n>` | `7357` | Port to listen on. |
| `--host <addr>` | `127.0.0.1` | Bind address. The default is loopback on purpose: the API exposes repository internals. |
| `--open` | `false` | Open the dashboard in the default browser. Failure to launch a browser is a warning, not an error. |
| `--no-analyze` | `false` | Skip the initial analysis and serve only recorded history. |
| `--shutdown-timeout <duration>` | `5s` | How long to wait for in-flight requests on shutdown. |

### API

| Endpoint | Returns |
| :--- | :--- |
| `GET /api/v1/health` | Current snapshot: overall score, per-component sub-scores, code, git, and dependency summaries, risk counts. |
| `GET /api/v1/history` | Recorded snapshots, oldest first. `?limit=N` caps the most recent N. |
| `GET /api/v1/risks` | Detected risks with full evidence payloads. `?severity=critical\|high\|medium\|low\|info` narrows the list; an unknown value is an error. |
| `GET /api/v1/hotspots` | Hotspot candidates and the churn table. `?confirmed=true` narrows to confirmed hotspots. |
| `GET /api/v1/version` | Tool version, JSON schema version, and whether this binary embeds a dashboard. |
| `GET /healthz` | Liveness. Does **not** run an analysis, so a monitor does not trigger a scan on every poll. |

All API responses carry `Cache-Control: no-store`. A cross-origin request is
refused: nothing on the internet is a legitimate caller of a loopback API that
returns repository internals.

```bash
lensyxe serve --open
lensyxe serve /path/to/repo --port 8080
```

## `lensyxe version`

Print the build metadata.

```
lensyxe version
```

```
Lensyxe Core v0.3.0
Commit:     8f3a9d2
Build Date: 2026-10-05T06:00:00Z
Built By:   goreleaser
Go Version: go1.22.0
OS/Arch:    linux/amd64
```

A binary built without injected metadata prints an additional
`Development build` notice, so a locally compiled build is never mistaken for
a release.

The values come from link-time variables:

```bash
go build \
  -ldflags "-X main.Version=0.3.0 \
            -X main.Commit=8f3a9d2 \
            -X main.Date=2026-10-05T06:00:00Z \
            -X main.BuiltBy=goreleaser" \
  ./cmd/lensyxe
```

## Configuration precedence

For every setting that exists in more than one place:

```
command-line flag  >  config file / LENSYXE_* env  >  built-in default
```

A missing or malformed config never aborts a run. Lensyxe warns on stderr and
falls back to the built-in defaults, so a typo in `.lensyxe.yml` degrades the
analysis rather than blocking it.

See [CONFIGURATION.md](CONFIGURATION.md) for the full file schema.
